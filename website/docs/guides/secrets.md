# Secrets

Secrets live in the repository, encrypted, next to the stack that uses them.
Only the server and the people listed as recipients can read them.

## File format

A secret file is a flat `KEY: value` map. Keys stay in clear text so diffs and
reviews make sense. Values are encrypted with AES-256-GCM using a random data
key, itself encrypted with age for every recipient.

```yaml title="stacks/blog/secrets.enc.yml"
DB_PASSWORD: ENC[v1,ziT+AOT4N9OAQvyg5Iv7...]
HOOK_TOKEN: ENC[v1,6FIrISb26J9nj6tHA60A...]
_minato:
  version: 1
  recipients: [age1server..., age1alice...]
  data_key: YWdlLWVuY3J5cHRpb24ub3JnL3YxCi0+...
  mac: a30163217d1efac2ba21a4e78e0bf48a...
```

- The key name is authenticated with its value, and a MAC covers the whole
  file: swapping or removing entries is detected.
- Unchanged values keep their ciphertext, so a git diff only shows what really
  changed.

## Two ways to edit

Every `minato secrets` command takes a **target**.

**A stack name** (`blog`): the server does the work through the API, on the
local socket or remotely after `minato login`. It decrypts with its own key,
commits as you, pushes to git and redeploys. You need no age key on your
laptop, but the deploy key needs write access to the repository.

**A file path** (`stacks/blog/secrets.enc.yml`): the file is edited in your
working copy with your own age key, then you commit and push.

```bash
minato secrets set blog DB_PASSWORD --random 32       # operator
cat cert.pem | minato secrets set blog TLS_CERT
minato secrets ls blog                                 # names only, viewer
minato secrets get blog DB_PASSWORD                    # admin
minato secrets edit blog                               # $EDITOR, one commit
minato secrets unset blog OLD_KEY
minato secrets rotate blog                             # new data key
minato secrets rotate blog --value DB_PASSWORD         # regenerate a value

minato secrets keygen                                  # ~/.config/minato/age.key
minato secrets edit stacks/blog/secrets.enc.yml        # local mode
minato secrets encrypt plain.yml -o stacks/blog/secrets.enc.yml
```

## Keys

| Who | Where the private key lives |
| --- | --- |
| Server | `/etc/minato/age.key`, generated by `minato server init` |
| You | `~/.config/minato/age.key`, or `$MINATO_AGE_KEY_FILE`, or `$MINATO_AGE_KEY` |

SSH public keys (`ssh-ed25519`, `ssh-rsa`) work as recipients too. To decrypt
with the matching private key, point `MINATO_AGE_KEY_FILE` at it, for example
`~/.ssh/id_ed25519` (passphrase protected keys are not supported).

After adding or removing a recipient in `.minato.yml`, run
`minato secrets rotate` on every file so the new list takes effect.

## Secret files instead of variables

Prefer `${secretfile.X}` with compose secrets over environment variables when
the image supports `*_FILE` variables:

```yaml
services:
  db:
    image: postgres:17
    environment:
      POSTGRES_PASSWORD_FILE: /run/secrets/db_password
    secrets: [db_password]
secrets:
  db_password:
    file: ${secretfile.DB_PASSWORD}
```

The file is written in the root only deploy folder, and nowhere else.
